# Stack-Based Mathematical Expression Evaluator

A Python program that reads several mathematical expressions from `input.txt`, evaluates each one with a **stack-based algorithm**, and writes the results to `output.txt` in the same layout.


## Features

- A `Stack` class with `push`, `pop`, `peek`, `is_empty` and `size` / `len()`.
- Evaluates `+`, `-`, `*`, `/` and parentheses `( )` using normal precedence rules.
- Operators with the same precedence are evaluated left to right (`8 / 4 * 2` = `4`).
- Whole and decimal numbers (`12`, `3.5`, `.25`).
- Unary signs (`-5`, `3 * -2`, `-(2 + 3)`).
- Uses the **shunting-yard algorithm** (operator stack) followed by **Reverse Polish Notation evaluation** (value stack). `eval()` and `exec()` are **not** used.
- Keeps separator lines (such as `-----`) and blank lines in their original positions.
- Invalid expressions produce a visible `ERROR: ...` line; the remaining expressions are still processed.
- Automated tests written with the standard-library `unittest` module.

## Requirements

- **Python 3.8 or newer** (developed and tested with Python 3.12.10 on Windows 11).
- No third-party packages. `requirements.txt` exists only to confirm this; there is nothing to install.

## Setup

### Windows (PowerShell)

```powershell
python --version
cd path\to\stack-implementation
```

If `python` is not recognised, install Python from <https://www.python.org/downloads/> and tick **"Add python.exe to PATH"** during installation (or try the `py` launcher: `py main.py`).

### macOS / Linux

```bash
python3 --version
cd path/to/stack-implementation
```

(Use `python3` instead of `python` in the commands below if needed.)

## How to run the program

```powershell
python main.py
```

This reads `input.txt` and writes `output.txt`. Both files are looked for in the folder that contains `main.py`, so the command works even when started from a different folder.

Optional — use different file names:

```powershell
python main.py examples\invalid_input.txt examples\invalid_output.txt
```

The program refuses to use the same file for input and output, so `input.txt` is never overwritten.

## How to run the tests

```powershell
python -m unittest -v
```

All tests should finish with `OK`.

## Input format

- One expression per line.
- A **separator line** is a line containing **three or more hyphens** and nothing else (spaces around them are allowed), e.g. `-----`.
- Spaces and tabs between numbers and operators are optional.
- Blank lines are allowed and are copied to the output as blank lines (they are **not** treated as zero).

Example `input.txt` 

```text
3 + 5 * 2
-----
(8 / 4) + 7 * 2
-----
10 - (2 + 3) * 4
```

The supplied `input.txt` contains these three expressions followed by seven more test expressions.

## Output format

Each expression line is replaced by its result; separator lines are copied exactly; everything stays on the same line number.

Output for the example above:

```text
13
-----
16
-----
-10
```

Number formatting:

- Whole-number results are written without a decimal point (`2.0` → `2`).
- Other results are rounded to at most 10 decimal places and trailing zeros are removed (`7 / 2` → `3.5`, `10 / 3` → `3.3333333333`).

## Error-handling policy

If an expression is invalid, its line in `output.txt` becomes `ERROR: <reason>`, the line number and reason are printed in the terminal, and the program continues with the next expression. A failed expression is never written as a number.

Detected problems: unsupported characters, missing operands (`3 + * 2`, `3 +`), missing operators (`3 4`, `2(3)`), unmatched `(` or `)`, invalid numbers (`1.2.3`), and division by zero.

Example — `examples/invalid_input.txt` produces `examples/invalid_output.txt`:

```text
ERROR: missing operand before '*' (position 5)
-----
ERROR: unmatched '(' - missing closing ')'
-----
ERROR: unmatched ')' - no opening '(' for it
-----
ERROR: division by zero
-----
ERROR: unsupported character '$' (position 3)
-----
ERROR: missing operator before '4' (position 3)
-----

-----
42
```

If `input.txt` itself is missing, the program prints `Error: input file not found` and exits with code 1.



## Troubleshooting

| Problem | Fix |
|---|---|
| `python` is not recognised | Install Python and add it to PATH, or use `py` instead of `python`. |
| `Error: input file not found` | Make sure `input.txt` is in the same folder as `main.py`. |
| A line shows `ERROR: ...` | Read the reason; check for typos, missing operators or unbalanced brackets. |
| `ModuleNotFoundError: stack` when running tests | Run the test command from the project folder. |
